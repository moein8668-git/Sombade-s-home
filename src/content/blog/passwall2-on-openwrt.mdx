تو این آموزش می‌خوایم باهم یه روتر OpenWrt رو تبدیل کنیم به یه فیلترشکن تمام‌عیار برای کل خونه. مسیرمون اینه: اول تایم‌زون و سرورهای زمان رو درست ست می‌کنیم (که اختیاریه ولی خیلی توصیه می‌شه)، بعد PassWall2 رو با پکیج‌منیجر جدید `apk` نصب می‌کنیم، با محیط پنلش آشنا می‌شیم، اولین کانفیگمون رو اضافه می‌کنیم و ترافیک همه دستگاه‌های خونه رو ازش رد می‌کنیم. بعدشم می‌ریم سراغ تفکیک هوشمند ترافیک ایران و خارج با Shunt Rule و FakeDNS که به نظرم جذاب‌ترین بخش ماجراست. ته مطلب هم یه آموزش کوچولو برای قشنگ کردن ظاهر پنل داریم. :)

## مرحله اختیاری ولی توصیه‌شده: تنظیم تایم‌زون و سرورهای زمان (NTP)

به نظرم این بخش رو اسکیپ نکنید مگر اینکه واقعاً عجله داشته باشید؛ چون یه سری مشکلات چرت‌ومسخره مثل ارورهای SSL دقیقاً از همین ساعتِ غلط روتر درمیاد و آدمو دیوونه می‌کنه.

اول بذارید بفهمیم اصلاً NTP چیه و چرا به کارمون میاد. **NTP** یا Network Time Protocol کاریه که ساعتِ روترمون رو با سرورهای زمان دنیا هماهنگ می‌کنه. حالا ربطش به SSL چیه؟ وقتی می‌خواید به یه سایت HTTPS وصل بشید، سیستم میاد تاریخ انقضای گواهینامه (Certificate) اون سایت رو چک می‌کنه. اگه ساعت روتر عقب یا جلو باشه، سیستم خیال می‌کنه گواهینامه هنوز معتبر نشده یا قبلاً منقضی شده و وسط کار بهتون ارور SSL می‌ده. پس درست بودن ساعت یعنی در امان موندن از ارورهای عجیب‌غریب.

بریم سراغ کار. اول سرورهای زمان رو به سرورهای داخل کشور تغییر می‌دیم که هم پاسخ‌شون سریع‌تره هم توی وضعیت فعلی اینترنت‌مون قابل اعتمادتر:

```bash
uci add_list system.ntp.server='ir.pool.ntp.org'
uci add_list system.ntp.server='ntp.time.ir'
```

بیایید ببینیم چی به چیه:

- `uci` — ابزاری که برای راحت‌تر ادیت کردن فایل‌های کانفیگ OpenWrt ساخته شده.
- `add_list` — یه مقدار جدید به یه لیست اضافه می‌کنه. سرورهای NTP چندتا هستن، برای همین به صورت لیست نگه داشته می‌شن.
- `system.ntp.server=` — مشخص می‌کنه کدوم بخش از کانفیگ رو داریم ست می‌کنیم؛ اینجا لیست سرورهای NTP زیر بخش system.
- `'ir.pool.ntp.org'` و بقیه — آدرس سرورهای زمان. `ir.pool.ntp.org` استخر سرورهای زمان ایرانه و مطمئن‌ترین انتخاب عمومی به حساب میاد؛ کنارش `ntp.time.ir` هم گزینه شناخته‌شده داخلیه. اگه شما سرور داخلی مطمئن‌تری سراغ دارید، همین دستورها رو با آدرس خودتون بزنید.

بعدش خودِ تایم‌زون و نام منطقه زمانی (Zone) رو ست می‌کنیم:

```bash
uci set system.@system[0].timezone='<+0330>-3:30'
uci set system.@system[0].zonename='Asia/Tehran'
```

توضیح هر بخش:

- `set` — برخلاف `add_list` که به لیست اضافه می‌کرد، اینجا یه مقدار تکی رو مستقیم می‌نویسه.
- `system.@system[0]` — داره به اولین (و معمولاً تنها) بلاک system توی فایل کانفیگ اشاره می‌کنه. اون `[0]` یعنی اولی.
- `timezone='<+0330>-3:30'` — فرمت استاندارد POSIX تایم‌زونه. `+0330` یعنی ۳ ساعت و ۳۰ دقیقه جلوتر از UTC که دقیقاً وقت رسمی ایرانه.
- `zonename='Asia/Tehran'` — اسم انسان‌پسند منطقه زمانی که سیستم ازش برای تشخیص ناحیه استفاده می‌کنه.

و در نهایت تغییرات رو ثبت و سرویس زمان رو ری‌استارت می‌کنیم:

```bash
uci commit system
service sysntpd restart
```

- `uci commit system` — این خیلی مهمه! تا این رو نزنید هیچ‌کدوم از تغییرات uci واقعاً روی دیسک ذخیره نمی‌شن و بعد از ری‌استارت می‌پرن.
- `service sysntpd restart` — سرویس NTP رو یه بار ری‌استارت می‌کنه تا با تنظیمات جدید بالا بیاد و ساعت سینک شه. (اسم سرویس `sysntpd` هست نه `ntpd`.)

## نصب پیش‌نیازها و PassWall2 (برای نسخه‌های ۲۵٫۱۲+)

خب رسیدیم به اصل مطلب. از اونجایی که نسخه‌های ۲۵٫۱۲ به بعد OpenWrt از `apk` استفاده می‌کنن (به‌جای opkg قدیمی)، پروسه نصب با خیلی از آموزش‌های قدیمی فرق داره. من همه‌چیز رو طبق داکیومنت رسمی مخزن PassWall2 جلو می‌برم که مطمئن باشیم چیزی از قلم نمی‌افته.

### آپدیت مخازن

اول مخازن رو آپدیت می‌کنیم تا لیست آخرین پکیج‌ها رو داشته باشیم:

```bash
apk update
```

### جایگزینی dnsmasq با نسخه کامل

یه نکته مهم: پکیج `dnsmasq` که به‌صورت پیش‌فرض روی OpenWrt نصبه، یه نسخه سبک (Lite) هست. PassWall2 برای تغییر مسیر شفاف DNS (Transparent Proxy) و کارهایی مثل ipset/nftset به قابلیت‌هایی نیاز داره که فقط توی `dnsmasq-full` هست. پس باید نسخه ساده رو حذف و نسخه کامل رو نصب کنیم؛ فقط حواستون باشه این دو تا کار رو **پشت سر هم و توی یه خط** انجام بدید:

```bash
apk del dnsmasq && apk add dnsmasq-full
```

چرا یه خط؟ چون بین حذف `dnsmasq` و نصب `dnsmasq-full` اگه فاصله بیفته، سرویس DNS روترتون برای چند لحظه خاموشه و حتی ممکنه حل شدن اسم دامنه برای دانلود خود پکیج جدید به مشکل بخوره. با `&&` مطمئنیم هر دو عملیات بدون وقفه پشت هم انجام می‌شن.

- `apk del dnsmasq` — نسخه ساده رو حذف می‌کنه. (اگه حذفش نکنید موقع نصب `dnsmasq-full` تداخل فایل می‌گیرید، چون هر دو یه باینری همنام دارن.)
- `&&` — یعنی «اگه دستور اول موفق بود، دومی رو هم اجرا کن».
- `apk add dnsmasq-full` — نسخه کامل با قابلیت‌های DNS پیشرفته نصب می‌شه.

### نصب ماژول‌های کرنل و ابزارها

```bash
apk add kmod-nft-tproxy kmod-nft-socket wget-ssl
```

ببینیم هر کدوم چی کاره‌ست:

- `kmod-nft-tproxy` — ماژول کرنل nftables که اجازه می‌ده ترافیک رو به‌صورت «شفاف» (بدون اینکه آدرس مقصد عوض بشه) به پروکسی PassWall2 هدایت کنیم. دقیقاً همون چیزیه که باعث می‌شه دستگاه‌های شبکه اصلاً نفهمن ترافیکشون داره از پروکسی رد می‌شه.
- `kmod-nft-socket` — ماژول دیگه‌ای برای nftables که اجازه می‌ده بر اساس سوکتِ سازنده ترافیک قانون بزنیم؛ مثلاً بگیم ترافیک خود روتر از پروکسی نره ولی ترافیک کلاینت‌ها بره.
- `wget-ssl` — نسخه wget با پشتیبانی HTTPS؛ چون قراره کلید و فایل‌ها رو از اینترنت دانلود کنیم.

### اضافه کردن کلید و مخازن PassWall2

حالا باید کلید امضای مخازن PassWall2 رو بگیریم تا `apk` بتونه پکیج‌ها رو تأیید (Verify) کنه:

```bash
wget -O /etc/apk/keys/passwall.pub https://sourceforge.net/projects/openwrt-passwall-build/files/apk.pub
```

- `wget` — برای دانلود فایل.
- `-O /etc/apk/keys/passwall.pub` — فایل دانلودشده رو با اسم `passwall.pub` توی مسیر کلیدهای apk ذخیره می‌کنه. مسیر `/etc/apk/keys/` دقیقاً همون جاییه که apk کلیدهای عمومی مخازن رو نگه می‌داره تا با هاشون امضای پکیج‌ها رو چک کنه.
- آدرس آخر هم فایل `apk.pub` روی SourceForge رسمی پروژه‌ست.

با این کلید apk می‌فهمه پکیج‌هایی که از مخازن PassWall می‌رسن واقعاً از جانب سازنده‌ان و دست‌کاری نشدن؛ برای همین نیازی به `--allow-untrusted` نیست که امنیت رو دور می‌زنه.

بعدش مخازن رو به لیست منابع apk اضافه می‌کنیم:

```bash
. /etc/openwrt_release
echo "release=${DISTRIB_RELEASE%.*} arch=$DISTRIB_ARCH"

for feed in passwall_packages passwall_luci passwall2; do
  echo "https://master.dl.sourceforge.net/project/openwrt-passwall-build/releases/packages-${DISTRIB_RELEASE%.*}/$DISTRIB_ARCH/$feed/packages.adb" >> /etc/apk/repositories.d/customfeeds.list
done

cat /etc/apk/repositories.d/customfeeds.list
```

بیایید خط به خط ببینیم چی داره می‌شه:

- `. /etc/openwrt_release` — این فایل رو Source می‌کنه؛ یعنی متغیرهای داخلش (مثل `DISTRIB_RELEASE` و `DISTRIB_ARCH`) مستقیم توی شل فعلی تعریف می‌شن.
- `echo "release=${DISTRIB_RELEASE%.*} arch=$DISTRIB_ARCH"` — یه sanity check کوچیک قبل از هر کاری؛ مقدارها رو نشونتون می‌ده (مثلاً `release=25.12 arch=x86_64`). اگه اینجا عدد یا معماری اشتباه دیدید، همینجا متوجه می‌شید و نمی‌رید آدرس غلط توی فایل مخازن بنویسید.
- `${DISTRIB_RELEASE%.*}` — آخرین بخش نقطه‌دار نسخه رو حذف می‌کنه (از `25.12.5` می‌شه `25.12`) چون ساختار آدرس مخازن با نسخه دو بخشی ساخته شده.
- `for feed in passwall_packages passwall_luci passwall2; do ... done` — حلقه‌ای که سه تا مخزن رو یکی‌یکی اضافه می‌کنه: `passwall_packages` (پکیج‌های اصلی و هسته‌ها)، `passwall_luci` (بخش‌های مشترک LuCI) و `passwall2` (خود اپلیکیشن).
- `>> /etc/apk/repositories.d/customfeeds.list` — آدرس هر مخزن رو به انتهای فایل منابع apk اضافه می‌کنه.
- `cat ...` — آخرش محتوای فایل رو نشون می‌ده تا چک کنید دقیقاً همون چیزی نوشته شده که انتظار داشتید.

⚠️ قبل از اجرا یه نگاه به محتوای فعلی فایل بندازید، چون ممکنه از قبل مخزن سفارشی دیگه‌ای توش داشته باشید:

```bash
cat /etc/apk/repositories.d/customfeeds.list 2>/dev/null
```

اگه فایل خالی بود یا اصلاً وجود نداشت، مشکلی نیست. اگه خطوط مربوط به passwall از قبل توش بود، یعنی قبلاً اضافه شدن و نیازی به تکرار نیست. اگه هم خطوط دیگه‌ای توش بود و خواستید دستی مدیریتش کنید، می‌تونید با `vi /etc/apk/repositories.d/customfeeds.list` بازش کنید و ویرایشش کنید.

اگه دوست دارید یکم بیشتر با basic های bash آشنا بشید، حتماً حتماً توصیه می‌کنم [آموزش Asa](https://linux-terminal-mastery.qubisuw.workers.dev/chapters/11-bash-scripting/) عزیز رو بخونید. واقعاً کمک می‌کنه به‌جای کورکورانه کپی کردن، بفهمید چی داره می‌شه.

### نصب خود PassWall2 و هسته‌ها

در نهایت دوباره مخازن رو آپدیت می‌کنیم (حالا با مخازن جدید) و پکیج‌ها رو نصب می‌کنیم:

```bash
apk update
apk add tcping geoview
apk add luci-app-passwall2
apk add sing-box
apk add xray-core
```

- `apk update` — لیست پکیج‌ها رو از همه مخازن (از جمله سه تای جدید) می‌گیره.
- `tcping` و `geoview` — دو تا ابزار کمکی که خود داکیومنت رسمی پیشنهادشون می‌کنه؛ اولی برای تست TCPing نودها توی پنل و دومی برای پردازش سریع‌تر فایل‌های GeoIP.
- `luci-app-passwall2` — رابط گرافیکی (وب‌پنل) PassWall2 که از تو پنل LuCI تنظیمش می‌کنید.
- `sing-box` و `xray-core` — دو تا انجین (هسته) پروکسی که PassWall2 ازشون استفاده می‌کنه.

⚠️ **و اما یه هشدار خیلی مهم درباره هسته Xray:** طبق اعلام رسمی پروژه، از ژوئن ۲۰۲۶ هسته Xray گزینه `allowInsecure` (رد کردن اعتبارسنجی گواهینامه) رو دیگه قبول نمی‌کنه و برای کانفیگ‌هایی با گواهینامه self-signed پارامتر `pinnedPeerCertSha256` (همون `pcs`) لازمه. عملاً یعنی اگه کانفیگتون (مثلاً VLESS یا Trojan با لینک‌هایی که ته‌شون `allowInsecure=1` داره) وصل نشد، یا `pcs` رو از ارائه‌دهنده کانفیگ بگیرید، یا توی تنظیمات نود، هسته اجراکننده رو روی **Sing-Box** بذارید که هنوز با حالت قبلی کار می‌کنه. جلوتر که رفتیم سراغ Node List، دوباره یادآوری‌ش می‌کنم.

خب اینجا کارمون با ترمینال تقریباً تمومه و می‌ریم از پنل وب کانفیگش کنیم.

## آشنایی با محیط و بخش‌های مختلف PassWall2

وقتی وارد پنل روترتون بشید و به مسیر **Services → PassWall 2** برید، به این صفحه رو‌به‌رو می‌شید که صفحه اصلی ماست و بیشتر کانفیگ‌های روزمره از همین تب **Basic Settings** انجام می‌شه.

<TutorialFigure src="/media/images/passwall2-on-openwrt/Pasted image 20260817120609.png" alt="صفحه اصلی تنظیمات PassWall 2 در OpenWrt" />

طبیعتاً قابلیت‌های پسوال خیلی بیشتر از اونیه که من همه‌شون رو بلد باشم یا بتونم توضیح بدم. اما بخش‌هایی که برای شروع کار لازم می‌شن رو کامل توضیح می‌دم؛ بعدش هر جا به مشکلی خوردید، با یکم ور رفتن با تنظیمات خودتون راه رو پیدا می‌کنید (فقط قبل ور رفتن، اسنپ‌شات یا بکاپ فراموش نشه 😉).

- **Core**: وضعیت اجرای هسته برنامه رو نشون می‌ده، به‌همراه یه سری دکمه تست اتصال با Baidu و گوگل و GitHub که چک می‌کنن واقعاً وصل شدید و دیتا رد می‌شه یا نه.

### تب‌های منو

- **Main**: صفحه اصلی تنظیمات و انتخاب سرور.
- **Shunt Rule**: تعریف قوانین روتینگ و تفکیک ترافیک (مسیریابی هوشمند سایت‌های داخلی و خارجی). این تب فقط وقتی فعال می‌شه که کانفیگی که برای Main Switch انتخاب کردید از نوع Shunt باشه؛ جلوتر کامل توضیح می‌دم.
- **DNS**: تنظیمات DNS اختصاصی، DoH و جلوگیری از نشت DNS (DNS Leak).
- **Log**: تنظیمات لاگ‌ها جهت عیب‌یابی.
- **FAQ**: سوالات پرتکرار و راهنمای خود ماژول.
- **Maintain**: پشتیبان‌گیری و بازنشانی تنظیمات.

### تنظیمات بخش Main

- **Main Switch**: کلید روشن/خاموش اصلی؛ با تیک زدن و ذخیره، کل سرویس اجرا می‌شه.
- **Node**: انتخاب کانفیگ/سرور مقصد برای اتصال.
- **Localhost Proxy**: اگه تیک بخوره، ترافیک خود سیستم‌عامل روتر (OpenWrt) هم از فیلترشکن عبور می‌کنه.
- **Client Proxy**: فعال‌سازی Transparent Proxy برای کلاینت‌ها؛ دستگاه‌های متصل به LAN و Wi-Fi بدون هیچ تنظیم خاصی، ترافیکشون از پراکسی رد می‌شه.
- **Node Socks Listen Port**: پورتی که هسته برای ارائه سرویس Socks5 محلی روش گوش می‌ده (پیش‌فرض `1070`).
- **Node Socks Bind Local**: در صورت فعال بودن، پورت Socks5 فقط از داخل خود روتر (`127.0.0.1`) در دسترسه. با غیرفعال کردنش، بقیه دستگاه‌های شبکه محلی هم می‌تونن از آی‌پی روتر و پورت ۱۰۷۰ به عنوان پراکسی استفاده کنن.

### بخش Socks Config

- **Socks Main Switch**: سوییچ فعال‌سازی تعریف پورت‌های Socks5 مستقل و اضافه (آخر مطلب کامل توضیح می‌دم).
- **جدول وضعیت نودها**: نمایش لیست پورت‌های فعال و نود اختصاص‌یافته به هرکدوم.

- **Direct Query Strategy**: استراتژی تفکیک دامنه برای ترافیک مستقیم (سایت‌های محلی/بدون فیلتر). گزینه `UseIP` بررسی می‌کنه دامنه به چه آی‌پی‌ای پاسخ می‌ده و بر اساس اون ترافیک رو مستقیم ارسال می‌کنه.
- **Remote DNS Protocol**: پروتکل ارتباط با DNS سرور خارجی (`TCP`، `UDP` یا DoH). توی وضعیت فعلی شبکه‌مون UDP رو توصیه می‌کنم، چون با بعضی پروتکل‌های دیگه اصلاً نمی‌تونید وصل بشید.
- **Remote DNS**: آدرس DNS سرور خارجی برای دامنه‌های فیلترشده (مثل `1.1.1.1` کلودفلر).
- **Remote DNS Outbound**: نحوه ارسال درخواست‌های DNS خارجی. مقدار `Remote` درخواست‌ها رو از داخل تانل/سرور پراکسی عبور می‌ده تا مسموم نشن (جلوگیری از DNS Poisoning).
- **Remote Query Strategy**: نوع رکورد درخواستی از سرور ریموت (`UseIPv4` یعنی فقط IPv4 دریافت و استفاده بشه).
- **Domain Override**: تنظیم دستی دامنه به آی‌پی (Static Host Mapping)؛ مثل آدرس خود سرورهای DNS برای جلوگیری از لوپ شدن درخواست‌ها.
- **DNS Redirect**: اجبار تمام کلاینت‌های شبکه به استفاده از همین DNS داخلی، تا کسی نتونه با DNS دلخواه خودش تنظیمات رو دور بزنه (ضد DNS Leak).
- **Clear NFTSET**: پاکسازی کش جدول‌های فایروال NFTables برای وقتایی که رول‌های جدید اعمال نمی‌شن.

## تب Log (تنظیمات ثبت گزارش)

<TutorialFigure src="/media/images/passwall2-on-openwrt/Pasted image 20260817125243.png" alt="تنظیمات تب Log در PassWall 2" />

- **Enable Node Log**: فعال یا غیرفعال کردن ثبت گزارش‌های اتصال و خطاهای نودها.
- **Log Level**: سطح جزئیات لاگ (`error` فقط خطاهای حیاتی رو ثبت می‌کنه؛ گزینه‌هایی مثل `info` یا `debug` گزارش مفصل‌تری می‌دن).
- **Log File / View Log**: مسیر ذخیره لاگ در حافظه موقت روتر (`/tmp/...`)؛ با کلیک روی **View Log** متن کامل لاگ‌ها باز می‌شه.

## تب Maintain (پشتیبان‌گیری و بازنشانی)

<TutorialFigure src="/media/images/passwall2-on-openwrt/Pasted image 20260817125825.png" alt="تب Maintain برای بک‌آپ و ریست تنظیمات" />

- **DL Backup (Create Backup File)**: دانلود فایل پشتیبان از تمام تنظیمات، رول‌ها و نودهای تعریف‌شده.
- **RST Backup (Restore Backup File)**: بازگردانی فایل بک‌آپ ذخیره‌شده.
- **Do Reset (Restore to default configuration)**: برگردوندن همه تنظیمات این ماژول به حالت پیش‌فرض کارخانه (حذف تمام کانفیگ‌ها).

## تب Node List

<TutorialFigure src="/media/images/passwall2-on-openwrt/Pasted image 20260817131208.png" alt="تب Node List برای مدیریت سرورها و نودها" />

- **Show server address and port**: نمایش آدرس IP/دامنه و پورت سرورها در جدول لیست نودها.
- **URL Test Address**: آدرس مقصد برای تست دانلود واقعی/HTTP پینگ (روی `Google` دیفالته).
- **Add**: افزودن دستی یه نود با پر کردن فرم مشخصات (پروتکل، آدرس، پورت و کلیدها).
- **Add the node via the link**: افزودن سریع نود با پیست کردن لینک اتصال (مثل `vless://`، `vmess://`، `ss://` یا `trojan://`).
- **Clear all nodes**: حذف یکجای همه نودهای موجود.
- **Delete select nodes**: حذف نودهایی که تیک چک‌باکسشون زده شده.
- **Reassign Group**: تغییر گروه یا دسته‌بندی نودهای انتخاب‌شده.
- **Save & Apply**: ذخیره لیست و اعمال تغییرات روی هسته برنامه.
- **Remarks / Ping / TCPing / URL Test / Use**: اسم یا توضیح نود، تست پینگ ICMP به سرور، تست زمان پاسخ TCP روی پورت سرور، تست واقعی دریافت دیتا از مقصد (مثلاً گوگل) و انتخاب مستقیم نود به عنوان نود فعال سوییچ اصلی.
- با اون آیکون ۶ نقطه هم می‌تونید کانفیگ‌ها رو بکشید بالا پایین تا لیستتون مرتب شه.

⚠️ یادآوری همون هشدار Xray: اگه نودتون وصل نمی‌شد ولی مطمئنید کانفیگش سالمه، وارد ادیت نود بشید و بخش انتخاب هسته (Core) رو چک کنید؛ برای پروتکل‌هایی مثل VLESS و Trojan می‌تونید به جای Auto/Xray، هسته **Sing-Box** رو انتخاب کنید. اگه مشکل از گواهینامه self-signed باشه، احتمالاً با همین کار حل می‌شه.

## تب Node Subscribe

<TutorialFigure src="/media/images/passwall2-on-openwrt/Pasted image 20260817131606.png" alt="تب Node Subscribe برای اضافه کردن سابسکرایب" />

**تعیین هسته اختصاصی برای هر پروتکل (Node Core Selection):**

- **Shadowsocks / Trojan / VMess / VLESS / Hysteria2 Node Use Type**: تعیین هسته اجراکننده (Core) برای هر پروتکل به صورت جداگانه. در حالت `Auto` سیستم بهترین هسته سازگار (Xray یا Sing-Box) رو خودکار انتخاب می‌کنه.

- **Manual subscription All**: به‌روزرسانی و دریافت مجدد نودها از تمام لینک‌های اشتراک به صورت همزمان.

## تب Rule Manage

<TutorialFigure src="/media/images/passwall2-on-openwrt/Pasted image 20260817132344.png" alt="تب Rule Manage برای آپدیت دیتابیس دامنه‌ها و آی‌پی‌ها" />

اینجا بخشیه که بعداً سر درست کردن کانفیگ Shunt قراره بالا سرش برگردیم.

- **GeoIP Update URL / Geosite Update URL**: لینک منبع دانلود و به‌روزرسانی دیتابیس آی‌پی کشورها (`geoip.dat`) و دیتابیس دسته‌بندی دامنه‌ها (`geosite.dat`).
- **Location of Geo rule files**: مسیر ذخیره فایل‌های ژئو روی حافظه روتر (`/usr/share/v2ray/`).
- **Auto Update Mode / Update Options**: زمان‌بندی آپدیت خودکار دیتابیس‌ها (روزانه، هفتگی یا `Disable`) و انتخاب اینکه کدوم دیتابیس‌ها آپدیت شن.
- **Manually update**: شروع دانلود و آپدیت دستی فایل‌های GeoIP و Geosite همون لحظه.

## عبور دادن ترافیک دستگاه‌های شبکه از روتر

خب تا همینجا شما فقط وی‌پی‌ان رو انداختید روی روتر، ولی هنوز هیچ دیوایسی تو شبکه ازش استفاده نمی‌کنه. برای اینکه دستگاهاتون اینترنت رو از روتر بگیرن، دوتا راه دارید:

### راه اول: خاموش کردن DHCP روی مودم اصلی و روشن کردنش روی روتر

برای خاموش کردنش روی مودم اصلیتون، چون هر مودمی UI خودش رو داره، یه سرچ ساده یا پرسیدن از هوش مصنوعی بهتر جواب می‌ده. برای روشن کردن DHCP روی روتر OpenWrt هم که قبلاً توی [آموزش نصب OpenWrt](/openwrt-on-proxmox) توضیح دادم؛ همون دستور خاموش شدن رو با یه تغییر کوچیک استفاده می‌کنیم:

```bash
uci set dhcp.lan.ignore='0'
uci commit dhcp
service dnsmasq restart
```

از طریق وب هم می‌تونید این کار رو بکنید: از منو `Network` برید توی `Interfaces`، اینترفیس `lan` خودتون رو انتخاب و `Edit` کنید، به تب `DHCP Server` و بعد `General Setup` برید و تیک `Ignore interface` رو بردارید.

### راه دوم: تنظیم دستی Gateway روی هر دستگاه

دستی توی هر دیوایستون تعریف کنید که از روتر اینترنت بگیرن. برای این کار باید وارد تنظیمات شبکه دیوایس بشید، مقادیر شبکه رو دستی پر کنید و برای قسمت Default Gateway، آدرس IP روترتون رو بزنید. اینطوری فقط همون دیوایس از روتر عبور می‌کنه و بقیه شبکه دست‌نخورده می‌مونه.

با انجام هرکدوم از این روش‌ها، ترافیک دیوایس‌ها از روی روتر و پسوال رد می‌شه (اگه تیک Client Proxy رو توی پسوال بردارید، ترافیک صرفاً از روتر رد می‌شه و دیگه به پسوال کاری نداره).

## تفکیک هوشمند ترافیک ایران و خارج (Shunt Rules)

حالا بریم برای بخش جذاب ماجرا: تفکیک ترافیک‌ها. بذارید اول توضیح بدم چی کار می‌خوایم بکنیم. یه لیست خیلی بزرگ آماده از دامنه‌ها و آی‌پی‌های ایرانی رو دانلود می‌کنیم و می‌ذاریم توی روتر، بعد به پسوال می‌گیم اگه خواستی به یه سری از این آی‌پی‌ها یا دامنه‌ها وصل شی، از فلان مسیر ما رو رد کن؛ که این فلان مسیر می‌تونه مستقیم باشه یا حتی یه کانفیگ دیگه. برای لیست بزرگمون هم هر لیستی که دوست دارید می‌تونید استفاده کنید؛ ما اینجا از **Chocolate4U/Iran-v2ray-rules** استفاده می‌کنیم.

### تنظیم Rule Manager و دانلود لیست‌ها

به بخش **Rule Manager** بیاید. قسمت‌های GeoIP Update URL و Geosite Update URL تعیین می‌کنن پسوال لیست‌هاش رو از کجا بگیره. از همین‌جا پیش می‌ریم. این دوتا رو روی `Chocolate4U/geoip (IR)` و `Chocolate4U/geosite (IR)` ست کنید و Auto Update Mode رو بذارید روی Everyday تا هر روز به شکل اتوماتیک این لیست‌ها به‌روز شن. Update Time هم خیلی مهم نیست، همون ۰۰:۰۰ بمونه. سیو و اپلای کنید و بعد روی Manually Update بزنید تا لیست آی‌پی و دامنه‌ها آپدیت و سینک شن با Chocolate4U/Iran-v2ray-rules. بعد از زدن این دکمه به صفحه لاگ برده می‌شید؛ صبر کنید تا بنویسه:

```
Running complete!
```

یعنی کار ما تمومه و می‌تونید لاگ رو ببندید یا اگه دوست داشتید Clear Log بدید تا تمیزتر بمونه. به Rule Manager برگردید.

<TutorialFigure src="/media/images/passwall2-on-openwrt/Pasted image 20260817152745.png" alt="تنظیم منابع Chocolate4U در Rule Manage" />

باید با یه همچین صفحه‌ای مواجه بشید. اگه به Sing-Box/Xray Shunt Rule دقت کنید، چند تا قانون پیش‌فرض می‌بینید. اگه خواستید مطالعه‌شون کنید و نگهشون دارید؛ ولی ما اینجا فقط می‌خوایم ترافیک ایران رو جدا کنیم و یاد بگیریم، پس من همه رو دیلیت می‌کنم و هرچی خودم بخوام دستی تعریف می‌کنم.

و اینجاست که به یه باگ می‌خوریم (امیدوارم شما برخورد نکنید)، ولی عیب نداره، همین‌جا با هم فیکسش می‌کنیم. وقتی همه رول‌ها رو پاک کنید، LuCI باگ می‌خوره و دکمه Add دیگه رندر نمی‌شه؛ پس مجبوریم به روش سخت و از ترمینال، اولین رول رو بسازیم.

برای این کار با این دستور یه رول خالی می‌سازیم:

```bash
uci add passwall2 shunt_rules
```

- **`uci`**: ابزاری که برای خواندن و ویرایش فایل‌های کانفیگ استفاده می‌کنیم.
- **`add`**: دستوری که یه سکشن بی‌نام (Anonymous Section) جدید به انتهای فایل کانفیگ اضافه می‌کنه.
- **`passwall2`**: نام فایل کانفیگ هدف که توی مسیر `/etc/config/passwall2` قرار داره.
- **`shunt_rules`**: نوع سکشن که مشخص می‌کنه بلاک ایجادشده یه قانون شانت/مسیریابیه.

حالا اسمش رو مشخص می‌کنیم:

```bash
uci set passwall2.@shunt_rules[-1].remarks='Iran'
```

- **`set`**: زیردستور افزودن یا تغییر مقدار یه گزینه (Option/Parameter).
- **`.` (نقطه)**: عملگر جداکننده بین فایل کانفیگ و سکشن مورد نظر.
- **`@shunt_rules[-1]`**: نحوه آدرس‌دهی سکشن بی‌نام:
  - علامت `@`: یعنی این سکشن نام اختصاصی (Named Section) نداره و باید بر اساس نوعش پیدا بشه.
  - `shunt_rules`: نوع سکشنی که قصد دسترسی بهش رو داریم.
  - `[-1]`: ایندکس آرایه‌ای در UCI (مشابه پایتون). عدد ‎-1‎ یعنی دقیقاً آخرین سکشن از نوع shunt_rules که توی فایل وجود داره (یعنی همون سکشنی که دستور قبل ساختیم).
- **`.remarks='Iran'`**: اینجا اسمی که می‌خواید رو بهش اختصاص می‌دید.

و در آخر ثبت قطعی تغییرات:

```bash
uci commit passwall2
```

- **`commit`**: اینم که قبلاً گفتیم؛ برای نوشتن و ثبت قطعی تغییرات روی حافظه دیسکه.

حالا اگه به پنل برگردید، می‌تونید ببینید یه رول برای ما ساخته شده و همچنین دکمه Add هم برگشته.

<TutorialFigure src="/media/images/passwall2-on-openwrt/Pasted image 20260818014312.png" alt="ایجاد قانون شانت جدید و بازگشت دکمه Add" />

اگه نبود، یه بار Log Out کنید و دوباره وارد پنل وب بشید.

برای اینکه با اد کردن و ادیت کردن از طریق وب هم آشنا بشید، یه بار هم اون مدلی بریم. توی فیلد اون پایین اسم دلخواهتون رو بذارید، مثلاً `iran2`، و بعد روی Add بزنید؛ همین. حالا برای ادیت هر دو رول به همین صفحه می‌رسیم. بیاید یکم بررسی کنیم ببینیم چیا دارن:

<TutorialFigure src="/media/images/passwall2-on-openwrt/Pasted image 20260818014808.png" alt="تنظیمات تطبیق ترافیک رول شانت بخش اول" />
<TutorialFigure src="/media/images/passwall2-on-openwrt/Pasted image 20260818014905.png" alt="تنظیمات تطبیق ترافیک رول شانت بخش دوم" />

- **Remarks**: نام یا برچسب قانون (اینجا `Iran`).
- **Shunt Rule Group**: دسته‌ای که این قانون توش قرار می‌گیره (مثلاً گروه `IR` برای جمع کردن رول‌های کشور ایران).

### فیلترهای تطبیق ترافیک (Match Conditions)

- **Protocol**: تفکیک پروتکل‌های ترافیکی مثل `http`، `tls`، `quic` یا bittorrent/تورنت. با تیک زدن هرکدوم، قانون فقط روی همون ترافیک اعمال می‌شه.
- **Inbound Tag**: تعیین ورودی ترافیک؛ مشخص می‌کنه این رول روی ترافیک شفاف کلاینت‌ها (`Transparent Proxy`) اعمال بشه یا ورودی‌های Socks محلی (`Socks`).
- **Network**: نوع پروتکل لایه انتقال شبکه (`TCP`، `UDP` یا ترکیب هر دو `TCP UDP`).
- **Source**: مبدا ترافیک؛ می‌تونید آی‌پی کلاینت خاص (مثل `192.168.1.100`)، رنج شبکه (CIDR مثل `192.168.1.0/24`) یا ترافیک داخلی (`geoip:private`) رو وارد کنید تا اجرای این رول محدود شه به دستگاه‌های خاص. با دکمه `+` هم اضافه می‌شن.
- **Port**: پورت یا بازه پورت مقصد (مثل `80,443` یا `1000-2000`). خالی گذاشتنش یعنی همه پورت‌ها رو شامل می‌شه.

### لیست دامنه‌ها (Domain)

اینجا و قسمت بعدی (آی‌پی‌ها) جاییه که ما کار داریم. ما اینجا قراره از یه دیتابیس لوکال (همون لیست خیلی بزرگمون) استفاده کنیم، ولی خب این قسمت ورودی‌های دیگه‌ای هم می‌گیره که خلاصه‌وار بگم:

- **دیتابیس لوکال**: مثل `geosite:ir` برای تمام دامنه‌های ثبت‌شده ایران یا `geosite:google`.
- **دامنه مستقیم**: مثل `example.com`.
- **زیردامنه**: به صورت `domain:example.com`.
- **دامنه دقیق**: به صورت `full:example.com`.
- **رجکس**: با شروع `:regexp`.
- **رول‌ست Sing-Box ریموت یا لوکال**: مثل `rule-set:remote:https://...` یا `rule-set:local:...` (خطوطی که با `#` شروع بشن کامنت حساب می‌شن و غیرفعالن).

### تطبیق بر اساس آی‌پی‌ها (IP)

- **IP (باکس متنی)**: تعریف آی‌پی‌های تکی، رنج‌های شبکه یا دیتابیس GeoIP:
  - آی‌پی تکی: مثل `1.1.1.1` یا `127.0.0.1`.
  - رنج شبکه: مثل `192.168.0.0/16`.
  - دیتابیس کشوری: مثل `geoip:ir` برای تمام آی‌پی‌های ایران یا `geoip:cn`.
  - رول‌ست‌های مستقیم Sing-Box: با فرمت `rule-set:remote:...` یا `rule-set:local:...`.
- **invert**: معکوس کردن نتیجه شرط‌ها؛ یعنی ترافیکی که با این شرایط **نمی‌خونه** گرفته شه (فقط روی هسته Sing-Box پشتیبانی می‌شه).

خب حالا بیاید رول مورد نیاز برای ترافیک داخلی رو تنظیم کنیم. توی قسمت Domain بنویسید:

```ini
geosite:ir
domain:ir
domain:xn--mgba3a4f16a
```

(اون خط آخر پونی‌کد دامنه ملی `.ایران` هست.) و توی قسمت IP بنویسید:

```ini
geoip:ir
```

بعدش سیو و اپلای کنید.

## ساخت کانفیگ Shunt و فعال‌سازی FakeDNS

خب حالا رول رو داریم، ولی کجا باید ازش استفاده کنیم؟ اینجاست که کانفیگ‌های از نوع Shunt به داد ما می‌رسن. به بخش **Node List** برید و روی **Add** بزنید تا یه کانفیگ رو به صورت دستی درست کنید. اسمش رو هر چی دوست دارید بذارید؛ من می‌ذارم `ir-r`. اگه دوست داشتید توی یه گروه هم قرارش بدید. تایپ هسته رو می‌تونید هم Xray بذارید هم Sing-Box؛ من اینجا با Xray جلو می‌رم. Protocol رو بذارید روی **Shunt**. Domain Strategy رو هم بذارید روی `IPIfNonMatch`. دیفالتش روی IPOnDemand هست که خب اگه بخواید می‌تونید توضیحات همون زیرش رو بخونید، ولی اگه بخوام خلاصه بگم:

- **Domain Strategy**: نحوه برخورد هسته با دامنه‌ها وقتی قوانین IP داریم:
  - `AsIs`: فقط از نام دامنه برای بررسی قوانین استفاده می‌کنه و در صورت عدم تطبیق، از قوانین IP استفاده نمی‌کنه.
  - `IPIfNonMatch`: اگه هیچ قانونی برای نام دامنه پیدا نشد، دامنه رو به IP ترجمه می‌کنه و بعد قوانین IP رو بررسی می‌کنه.
  - `IPOnDemand`: به محض اینکه قانونی مبتنی بر IP توی لیست وجود داشته باشه، بلافاصله دامنه رو به IP ترجمه می‌کنه تا بررسی بشه.

خیلی از آموزش‌ها از همون IPOnDemand استفاده می‌کنن؛ من خودم IPIfNonMatch رو ترجیح می‌دم چون اول به قوانین دامنه فرصت کامل می‌ده.

**FakeDNS Main Switch** رو هم روشن کنید.

<TutorialFigure src="/media/images/passwall2-on-openwrt/Pasted image 20260819122854.png" alt="کانفیگ Shunt اختصاصی برای تفکیک ترافیک ایران و خارج" />

یه توضیح ریز درباره یه سری از تنظیمات اینجا هم داشته باشیم:

- **Direct DNS result write to IPSet**: با فعال بودن این گزینه، نتایج دامنه‌های مستقیم وارد جدول IPSet/NFTSet فایروال می‌شه و ترافیک‌های بعدی بدون ورود به هسته Xray، مستقیماً از طریق فایروال لینوکس عبور می‌کنن (کاهش چشمگیر مصرف CPU روتر).
- **Enable GeoIP Data Parsing**: پیش‌بارگذاری و آنالیز دیتابیس GeoIP توی حافظه برای بالا بردن سرعت روتینگ (مصرف رم روتر رو کمی افزایش می‌ده).

### مکانیزم FakeDNS چطوری کار می‌کنه؟

گزینه FakeDNS Main Switch یکم پیچیده‌تره؛ بذارید با حوصله توضیحش بدم. توی حالت عادی وقتی می‌خواید مثلاً youtube.com رو باز کنید، اول درخواست DNS از کلاینت شما به روتر می‌ره. روتر باید از طریق تانل پروکسی بره درخواست DNS بزنه تا آی‌پی youtube.com رو دربیاره، بعد این رو بده به کلاینت و بعد کلاینت بیاد و اتصال رو به اون آی‌پی برقرار کنه. یعنی قبل از باز شدن سایت، یه رفت‌وبرگشت کامل DNS از داخل تانل لازمه.

اما وقتی از FakeDNS استفاده می‌کنیم، وقتی کلاینت به روتر می‌گه «آی‌پی youtube.com رو بهم بده»، روتر به جای رفتن توی تانل و درآوردن آی‌پی اصلی، خیلی سریع یه **آی‌پی جعلی لوکال** به کلاینت برمی‌گردونه و توی حافظه‌ش یادداشت می‌کنه که «این آی‌پی جعلی = youtube.com». کلاینت هم که فکر می‌کنه این آی‌پی واقعی youtube.com هست، شروع می‌کنه به وصل شدن بهش. پکت‌ها که به روتر می‌رسن، روتر از روی آی‌پی مقصد یادداشتش رو چک می‌کنه، می‌فهمه این همون youtube.com بوده، هدر درخواست رو تغییر می‌ده و به جای آی‌پی، اسم واقعی دامنه رو می‌ذاره؛ بعد همین درخواست رو از تانل می‌فرسته برای سرور خارج و بهش می‌گه «خودت به youtube.com وصل شو».

چند تا مزیت هم داره: تأخیر اولیه باز شدن سایت‌ها کم می‌شه (چون رفت‌وبرگشت DNS از داخل تانل حذف می‌شه)، جلوی مسموم شدن DNS گرفته می‌شه و سرویس‌هایی که به تفاوت لوکیشن DNS و آی‌پی حساسن راحت‌تر باز می‌شن.

⚠️ **یه نکته مهم:** این قابلیت روی پروکسی‌هایی که از دامنه ساپورت می‌کنن خوب کار می‌کنه، ولی اگر یه پروکسی‌ای فقط به IP وصل بشه این درست کار نمی‌کنه.

حالا می‌رسیم به جدول رول‌ها؛ می‌بینید که یه دیفالت داره و رولی که برای ایران ساختیم رو خودکار پیدا کرده. برای هر رول می‌تونید یه نود جدا انتخاب کنید. برای اینکه همه ترافیک از نود (مثلاً همون VLESS) رد بشه و ایران دایرکت بره، کافیه نود رول ایران رو بذارید روی **Direct Connection**. برای رول دیفالت هم یه کانفیگ پروکسی به دلخواه انتخاب کنید. برای اینکه از FakeDNS استفاده کنیم، بعد از انتخاب یه نود پروکسی برای رول دیفالت، جلوش یه چک‌باکس FakeDNS میاد که اگه می‌خواید از FakeDNS استفاده کنید باید روشنش کنید.

حالا ممکنه بپرسید «ما که یه بار بالای صفحه این تیک رو زدیم، چرا برای هر رول پروکسی باید دوباره مشخصش کنیم؟» دلیلش اینه که ممکنه شما چند تا رول مختلف داشته باشید که هرکدوم برای کار خاصی طراحی شدن (مثلاً یکی برای استریم، یکی برای گیم) و نخواید همه‌شون از مکانیزم FakeDNS عبور کنن؛ بعضی سرویس‌ها با آی‌پی جعلی قاطی می‌کنن. برای همین تصمیم نهایی برای هر مسیر، جداگانه به عهده خودتون گذاشته شده.

- **Preproxy**: به رول شما یه پروکسی واسط اضافه می‌کنه؛ یعنی اول ترافیک از Preproxy رد می‌شه و بعد از طریق اون به نودی که تعریف کردید می‌رسه. برای حالت‌هایی که می‌خواید پروکسی زنجیره‌ای داشته باشید به درد می‌خوره.

## ساخت پورت اختصاصی Socks5 / HTTP

خب تا الان شما پسوال رو به خوبی کانفیگ کردید، یه شناخت خوب ازش به دست آوردید و دستگاه‌هاتون رو بردید پشت یه پروکسی که روتینگ رول هم داره. فقط موند Socks Configها. به بخش **Basic Settings** اگه بیاید، پایین یه جدول برای Socks Config گذاشته. کاربردش اینه: اگه سیستمی یا نرم‌افزاری از پروکسی Socks یا HTTP پشتیبانی کنه، لازم نیست کل اون سیستم رو ببرید پشت روتر و از کانفیگ رد کنید؛ فقط همون اپ رو تنظیم می‌کنید تا از این پروکسی Socks استفاده کنه.

برای این کار تیک **Socks Main Switch** رو بزنید و Save & Apply کنید، بعدش از دکمه **Add** اون پایین یه کانفیگ Socks درست کنید. نودش رو هر چیزی دوست دارید بذارید. **Socks Listen Port** رو هم یه پورت آزاد بدید که جای دیگه‌ای استفاده نشده باشه. اگه می‌خواید در کنارش پروکسی HTTP هم فعال بشه، توی فیلد پورت HTTP یه پورت جدا بذارید تا با پورت Socks تداخل نداشته باشه (به صورت پیش‌فرض روی 0 هست که یعنی پروکسی HTTP خاموشه، ولی اگه یه پورت بهش بدید، پروکسی HTTP روی همون پورت اجرا می‌شه).

<TutorialFigure src="/media/images/passwall2-on-openwrt/Pasted image 20260819125523.png" alt="افزودن پورت Socks5 مستقل" />

کافیه Save & Apply کنید و به منوی اصلی برگردید.

<TutorialFigure src="/media/images/passwall2-on-openwrt/Pasted image 20260819125557.png" alt="وضعیت فعال شدن Socks در صفحه اصلی" />

اون تیک‌های ردیف Status نشون می‌دن که پروکسی Socks ما آماده‌ست یا نه؛ اگه HTTP رو هم ست کرده باشید، دوتا تیک نشون می‌ده. برای استفاده ازش کافیه توی هر برنامه‌ای که پروکسی قبول می‌کنه، آدرس رو این مدلی بدید:

```bash
socks5://router_ip:port
```

که به‌جای `router_ip` آی‌پی روترتون و به‌جای `port` همون پورتی که تعریف کردید.

## بخش اضافه: زیباسازی و نصب تم Fluent روی LuCI

خیلی خب، الان دیگه می‌تونید PassWall2 خودتون رو به خوبی تنظیم کنید و ازش استفاده کنید. چون تا این‌جای کار همراه بودید و اومدید، یه آموزش کوچولو و بامزه همین‌جا ریز داشته باشیم :))

اگه از UI بی‌روح روتر خسته شدید، باید بگم OpenWrt به ما اجازه می‌ده تم خودمون رو بسازیم یا یه تم آماده رو روی روتر نصب کنیم. تعداد خیلی زیادی تم نوشته شده که خودتون اگه خواستید می‌تونید سرچ بزنید و پیدا کنید، یا مثلاً از [داکیومنت تم‌های OpenWrt](https://openwrt.org/docs/guide-user/luci/luci.themes) یه تعدادی تم که خود OpenWrt لیست کرده رو ببینید و هرکدوم رو خواستید نصب کنید. من خودم یه زمان زیادی روی تم Argon بودم، ولی یه چند وقتیه از [Fluent](https://github.com/LazuliKao/luci-theme-fluent) استفاده می‌کنم و به نظرم قشنگ‌تره. اینجا هم همون رو آموزش می‌دم که راحت نصبش کنید. نصب بقیه هم اگه بر اساس داکیومنت خودشون پیش برید، هیچ چیز خاصی نداره.

### روش اول: نصب خودکار با اسکریپت

ساده‌ترین روش، اسکریپت نصب رسمیه؛ یعنی همین یه خط رو توی ترمینال می‌زنید و تمام:

```bash
wget -qO- https://raw.githubusercontent.com/LazuliKao/luci-theme-fluent/main/install.sh | sh
```

⚠️ یه نکته امنیتی دوستانه: الگوی `wget ... | sh` یعنی «اسکریپت اینترنت رو مستقیم با دسترسی root اجرا کن». قبلش یه نگاه به محتوای اسکریپت بندازید (لینک رو توی مرورگر باز کنید) و مطمئن شید منبعش معتبره. اینجا اسکریپت رسمی مخزن Fluent هست و مشکلی نداره، ولی این عادت رو همیشه با هر مخزنی چک کنید.

### روش دوم: نصب دستی فایل پکیج

ولی از اونجایی که نصب این یکی خیلی ساده‌ست، یه توضیحی هم درباره نصب دستی می‌دم که بعداً اگه جایی دیدید، یه آشنایی داشته باشید. باید فایل `apk` یا `ipk` (بسته به نسخه روترتون) رو دانلود کنید (۲۵٫۱۲ به بالا باید از apk استفاده کنن) که می‌تونید با wget این کار رو انجام بدید. بعدش کافیه برید توی پوشه‌ای که دانلود کردید و فایل رو دستی نصب کنید؛ مثلاً اگه `luci-theme-fluent-1.0.9-r1.apk` رو دانلود کردید، باید بزنید:

```bash
apk add ./luci-theme-fluent-1.0.9-r1.apk
```

که درواقع دارید به پکیج‌منیجر می‌گید این فایلی که دانلود کردم رو نصبش کن. یا برای نسخه‌های قدیمی‌تر روتر (opkg):

```bash
opkg install ./luci-theme-fluent_1.0.9-r1_all.ipk
```

بعدش توی پنل وب یه بار Logout و Login کنید و به **System → System → Language and Style** برید و Design رو بذارید روی تم **Fluent** که همین الان نصب کردیم؛ سیو و اپلای و تمام. اگه هم خواستید توی تنظیمات خود تم تغییری بدید، به **System → System → Fluent Theme** برید و اونجا می‌تونید تغییراتتون رو بدید یا حتی تم رو آپدیت کنید.

⚠️ در نظر داشته باشید بعضی پکیج‌ها ممکنه با تم‌های غیر از تم دیفالت یه مشکلات ریز بخورن؛ چون بیشترشون برای تم اصلی طراحی می‌شن. معمولاً چیز جدی‌ای پیش نمیاد و هر وقت خواستید، از Language and Style برمی‌گردونیدش رو تم دیفالت روتر.
